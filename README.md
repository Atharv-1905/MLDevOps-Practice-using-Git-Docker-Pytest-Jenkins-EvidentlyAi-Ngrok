# Student Marks Analyzer — Automated DevOps CI/CD Pipeline

A Python-based Student Marks Analyzer project demonstrating an automated DevOps workflow using **GitHub, Jenkins, Docker, Pytest, ngrok, and Evidently AI**.

The project uses a GitHub webhook exposed through ngrok to trigger Jenkins automatically whenever new code is pushed to GitHub. Jenkins then checks out the latest source code, executes tests, builds a Docker image, runs the application and tests inside Docker, performs data drift monitoring, and archives the generated HTML report.

## 1. Project Objectives

- Develop a Python application to analyze student marks.
- Maintain and version-control source code using Git and GitHub.
- Automate builds using GitHub Webhooks and Jenkins.
- Expose the local Jenkins server to GitHub through ngrok.
- Run automated tests using Pytest.
- Containerize the application using Docker.
- Perform data drift monitoring using Evidently AI.
- Generate and archive an HTML data drift report.
- Demonstrate Continuous Integration (CI) through an automated pipeline.

## 12. GitHub Webhook and ngrok Integration

The webhook integration allows GitHub to notify Jenkins whenever a push event occurs, triggering a new pipeline build without manually clicking **Build Now**.

### Step 1: Start Jenkins

Ensure Jenkins is running and accessible locally:

```text
http://localhost:8080
```

### Step 2: Start ngrok

Expose the local Jenkins port through an HTTPS tunnel:

```bash
ngrok http 8080
```

ngrok provides a public HTTPS forwarding address. Keep the ngrok process running while you expect GitHub webhook events to reach Jenkins.

### Step 3: Configure the GitHub webhook

In the GitHub repository:

1. Open **Settings**.
2. Select **Webhooks**.
3. Open the webhook you created.
4. Configure its Payload URL to use the HTTPS ngrok address with the Jenkins GitHub webhook endpoint:

   ```text
   https://YOUR-NGROK-DOMAIN/github-webhook/
   ```

5. Select `application/json` as the content type.
6. Select the **Just the push event** option if you only want builds triggered by pushes.
7. Save the configuration.

Replace `YOUR-NGROK-DOMAIN` with the active domain provided by ngrok.

### Step 4: Configure Jenkins

Open the `student-marks-pipeline` job and select **Configure**.

Under the build triggers, enable:

```text
GitHub hook trigger for GITScm polling
```

Save the configuration.

The Jenkins GitHub integration must be installed and configured appropriately for this trigger to work.

### Step 5: Verify automatic triggering

Make a code or documentation change and push it to GitHub:

```bash
git add README.md
git commit -m "Update project documentation"
git push origin main
```

After GitHub delivers the webhook event, Jenkins should automatically schedule a new build.

Verify the result by opening the Jenkins job and checking the latest build and its Console Output.

### Important considerations

- Keep ngrok running while using the tunnel.
- A temporary ngrok URL may change after restarting ngrok. Update the GitHub webhook URL if the public domain changes.
- Verify webhook delivery status in GitHub under **Settings → Webhooks → Recent Deliveries**.
- Do not expose Jenkins publicly without appropriate authentication and security controls.
- Use a webhook secret when supported and configured on both sides.

## 13. Jenkins CI Pipeline

The Jenkins pipeline automates the following stages:

| Stage | Description |
|---|---|
| Pull Code from GitHub | Retrieves the latest code from `main` |
| Setup Python | Creates a Python virtual environment and installs Pytest |
| Run Tests | Runs automated Python tests |
| Docker Build | Builds the Docker image |
| Docker Application Test | Executes the application in Docker |
| Docker Pytest | Runs tests inside Docker |
| Evidently Monitoring | Executes drift analysis and generates the report |
| Archive Artifacts | Archives the HTML report after a successful pipeline |

### How the automated workflow operates

1. A developer pushes code to GitHub.
2. GitHub sends a push-event webhook to the ngrok HTTPS endpoint.
3. ngrok forwards the request to Jenkins.
4. Jenkins schedules the pipeline.
5. The pipeline checks out the latest code and runs its configured stages.
6. Jenkins records the build result and archives the report when the pipeline succeeds.

A successful build should end with a status similar to:

```text
SUCCESS: All CI stages completed!
Jenkins pipeline execution finished.
Finished: SUCCESS
```

To inspect the generated report, open the successful build and look under **Build Artifacts** for:

```text
monitoring/reports/drift_report.html
```

If Jenkins displays the HTML source rather than the report, download the artifact and open the downloaded file locally in Chrome or Firefox.

## 15. Troubleshooting

### Jenkins does not build automatically

- Check that the ngrok tunnel is running.
- Confirm the GitHub webhook Payload URL uses the active HTTPS ngrok address.
- Inspect webhook delivery status in GitHub.
- Verify that the Jenkins job has **GitHub hook trigger for GITScm polling** enabled.
- Check Jenkins logs and job configuration.

### Jenkins cannot access Docker

Verify Docker:

```bash
docker version
```

Ensure the Jenkins service account has the required Docker permissions. Membership in the Docker group grants powerful privileges, so configure access carefully.

### The report is missing

Create the report directory:

```bash
mkdir -p monitoring/reports
```

Confirm that `monitoring/data_drift.py` saves the report to:

```text
monitoring/reports/drift_report.html
```

Ensure the Jenkins monitoring stage mounts the report directory so the file persists after the temporary container exits.

### Jenkins pipeline fails

Open the failed build and inspect **Console Output**. Identify the first failed stage before making changes.
